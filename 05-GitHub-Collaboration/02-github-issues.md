# GitHub Issues

## Overview

GitHub Issues are a project management feature used to track tasks, bugs, feature requests, and improvements within a repository.

They help teams organize work, communicate problems, and monitor project progress.

GitHub Issues are commonly used in professional software development and open-source projects.

---

# What is a GitHub Issue?

A GitHub Issue is a record of a task, problem, or request that needs attention.

Examples:

```
Bug:
Dashboard shows incorrect sales calculation

Feature:
Add customer segmentation analysis

Task:
Update project documentation
```

---

# Why Use GitHub Issues?

GitHub Issues help teams:

- Track bugs
- Manage tasks
- Request new features
- Assign responsibilities
- Discuss solutions
- Maintain project history

---

# Common Types of Issues

## Bug Report

Used when something is not working correctly.

Example:

```
Title:

Fix incorrect profit calculation

Description:

Profit values are different from source data.
```

---

## Feature Request

Used when requesting a new improvement.

Example:

```
Title:

Add monthly sales trend chart

Description:

Create visualization showing monthly revenue patterns.
```

---

## Task

Used for general project activities.

Example:

```
Title:

Update README documentation

Description:

Add installation and usage instructions.
```

---

# GitHub Issue Workflow

Professional workflow:

```
Create Issue

      ↓

Assign Team Member

      ↓

Work on Solution

      ↓

Create Branch

      ↓

Commit Changes

      ↓

Create Pull Request

      ↓

Close Issue
```

---

# Creating an Issue

Steps:

1. Open GitHub repository
2. Select Issues tab
3. Click New Issue
4. Add title
5. Describe the problem or task
6. Add labels
7. Assign members
8. Create issue

---

# Issue Components

A professional issue contains:

## Title

The title should clearly explain the task.

Good:

```
Fix missing customer records in dashboard
```

Avoid:

```
Problem
```

---

## Description

A good description includes:

- Problem details
- Expected behavior
- Current behavior
- Possible solution

Example:

```
Problem:

Sales dashboard displays incorrect totals.

Expected:

Dashboard total should match SQL calculation.

Solution:

Review aggregation logic.
```

---

# Labels

Labels help categorize issues.

Common labels:

```
bug
feature
documentation
enhancement
question
urgent
```

Example:

```
Fix SQL calculation

Labels:
bug
high-priority
```

---

# Assigning Issues

Issues can be assigned to team members.

Example:

```
Issue:

Create Power BI dashboard

Assigned:

Data Analyst
```

This defines responsibility.

---

# Milestones

Milestones group related issues together.

Example:

```
Milestone:

Version 1.0 Release

Issues:

✓ Complete dashboard
✓ Update documentation
✓ Fix calculations
```

---

# Linking Issues with Pull Requests

GitHub allows issues to connect with Pull Requests.

Example:

Pull Request description:

```
Fixes #25
```

When the PR is merged:

```
Issue #25 automatically closes
```

# Issues vs Pull Requests

| GitHub Issues | Pull Requests |
|---|---|
| Track tasks and problems | Review code changes |
| Plan work | Merge completed work |
| Discuss requirements | Discuss implementation |
| Created before development | Created after development |

# Interview Questions

## 1. What are GitHub Issues?

GitHub Issues are tools used to track bugs, tasks, feature requests, and project discussions.

---

## 2. Difference between Issues and Pull Requests?

Issues track work requirements, while Pull Requests review and merge completed changes.

---

## 3. Why are labels used in GitHub Issues?

Labels categorize issues and make project management easier.

---

## 4. What are milestones?

Milestones group related issues to track progress toward a release or goal.
